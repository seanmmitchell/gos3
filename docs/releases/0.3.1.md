# gos3 0.3.1

gos3 is an S3-compatible object storage server with an embedded or standalone
web console. It supports local and remote S3 backings, IAM and bucket policies,
versioning and Object Lock, replicas, encryption, copy and mirror jobs, and
restic backup and recovery. This patch release fixes a bucket-move cutover
failure and updates the web dependency graph to address reported security
alerts.

[Download v0.3.1](https://github.com/seanmmitchell/gos3/releases/tag/v0.3.1)
or see the [changes since v0.3.0](https://github.com/seanmmitchell/gos3/compare/v0.3.0...v0.3.1).
The [v0.3.0 release](https://github.com/seanmmitchell/gos3/releases/tag/v0.3.0)
describes the preceding update.

## Changes since 0.3.0

- **Safer bucket moves and failover.** A move now saves the new placement
  before purging the source copy. If saving fails, the cutover is undone and
  retried while the source remains intact. Failed background placement saves,
  including automatic failover, are retried until the current placement is
  persisted. This avoids restoring a stale placement after a restart.
- **Web dependency security updates.** Nuxt, Happy DOM, undici, node-forge and
  serialize-javascript were updated for the reported advisories. Vue, Vue
  Router and the Vite override were aligned with Nuxt. CI now runs
  `pnpm audit --audit-level high`. See the
  [security PR](https://github.com/seanmmitchell/gos3/pull/114) for the
  dependency changes and validation.
- **Further dependency fixes.** The Python compatibility suite now uses
  `pyasn1` 0.6.5 for four decoder denial-of-service advisories. The web lockfile
  uses `glob` 14.0.2 and `minimatch` 11.0.1 for the two reported traversal and
  pattern-amplification advisories. Rollup's node resolver uses `deepmerge`
  4.1.1 with a local prototype-key filter because a direct hostile-input test
  reproduced the issue even below the advisory's listed affected range;
  upstream has not published a patched release. These changes affect test and
  build tooling, not the gos3 server's runtime dependencies.

## Install 0.3.1

| Distribution | Choose |
|---|---|
| Binary with console | `gos3_0.3.1_<os>_<arch>.tar.gz` (`.zip` on Windows) |
| Headless binary | `gos3_0.3.1_<os>_<arch>-headless.tar.gz` (`.zip` on Windows) |
| Container with console | `ghcr.io/seanmmitchell/gos3:0.3.1` |
| Headless container | `ghcr.io/seanmmitchell/gos3:0.3.1-headless` |

Archives cover Linux, macOS and Windows on amd64 and arm64; images cover
Linux amd64 and arm64. Both image variants include restic. Install restic
separately beside a binary if you use restic-backed storage or backups.
Follow the [quick start](../../README.md#quick-start) or the
[deployment guide](../deployment.md). Source builds require Go 1.26.10 or
newer; building the console also requires Node.js 22 and pnpm.

Check an archive against `checksums.txt` and verify its signed build
provenance. Verify a container image and pin the verified digest. For example:

```sh
gh attestation verify gos3_0.3.1_linux_amd64.tar.gz \
  --repo seanmmitchell/gos3 --source-ref refs/heads/main
gh attestation verify oci://ghcr.io/seanmmitchell/gos3:0.3.1 \
  --repo seanmmitchell/gos3 --source-ref refs/heads/main
```

## Upgrading from 0.3.0

1. Back up backing data, metadata, settings, credentials, encryption keys and
   restic repositories before upgrading. Keep the backup for rollback; see
   the [backup guide](../operations.md#backups).
2. If a bucket move is in progress, let it finish or pause it before
   replacing the server. After restarting, check its placement and the
   source and target copies before resuming writes that depend on the move.
3. Upgrade the binary or image, restart, confirm `gos3 version` and
   `/_gos3/ready`, then test a signed upload and read. Existing configuration
   and storage formats do not require a migration for this patch.

If you upgrade from an earlier release, also follow its upgrade notes. A
backup is the reliable rollback path if an older build cannot read data
written by a newer one.

## Known limits

The release does not add distributed clustering, STS/session tokens, AWS KMS,
SSE-C or erasure coding. Replicas and mirror jobs do not replace backups.
See the [compatibility reference](../s3-compatibility.md) and
[security guide](../security.md). Review the repository's
[Dependabot alerts](https://github.com/seanmmitchell/gos3/security/dependabot)
for newly disclosed findings after this release.
