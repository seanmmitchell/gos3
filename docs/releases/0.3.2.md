# gos3 0.3.2

gos3 is an S3-compatible object storage server with an embedded or standalone
web console. It supports local and remote S3 backings, IAM and bucket policies,
versioning and Object Lock, replicas, encryption, copy and mirror jobs, and
restic backup and recovery. This patch release corrects console version labels
and updates Go and web dependencies for security fixes.

[Download v0.3.2](https://github.com/seanmmitchell/gos3/releases/tag/v0.3.2)
or see the [changes since v0.3.1](https://github.com/seanmmitchell/gos3/compare/v0.3.1...v0.3.2).
The [0.3.1 overview](0.3.1.md) covers the preceding bucket-move and dependency fixes.

## Changes since 0.3.1

- **Correct server version labels (#122).** The Servers list, sign-in page,
  discovery results and peer table display the server-reported version unchanged.
  `v0.3.1` no longer becomes `vv0.3.1`, and development builds remain `dev`.
  Twelve rendering regression cases cover all four views.
- **Patched Go toolchains (#122).** Source and CI builds require Go 1.26.11
  for the standard-library fix identified by GO-2026-6859. The container builder
  uses Go 1.27.4, pinned to its official multi-platform image digest.
- **Nuxt and Forge security updates (#123).** Nuxt and its framework packages
  move to 4.6.4 for the leading-`//` page-route middleware bypass and development
  server workspace-file exposure. `node-forge` is pinned to 1.4.3 for HTTP header
  denial of service, TLS client crashes and Ed25519 verification fixes. Required
  Nitro and routing dependencies are updated with exact-version cooldown
  exceptions. Earlier security overrides and the local `deepmerge` prototype-key
  filtering patch are retained. The unused optional Terser worker is removed;
  standalone server output remains unminified.

See [#122](https://github.com/seanmmitchell/gos3/pull/122) and
[#123](https://github.com/seanmmitchell/gos3/pull/123) for implementation,
security review and validation evidence.

## Install 0.3.2

| Distribution | Choose |
|---|---|
| Binary with console | `gos3_0.3.2_<os>_<arch>.tar.gz` (`.zip` on Windows) |
| Headless binary | `gos3_0.3.2_<os>_<arch>-headless.tar.gz` (`.zip` on Windows) |
| Container with console | `ghcr.io/seanmmitchell/gos3:0.3.2` |
| Headless container | `ghcr.io/seanmmitchell/gos3:0.3.2-headless` |

Archives cover Linux, macOS and Windows on amd64 and arm64; images cover
Linux amd64 and arm64. Both image variants include restic. Install restic
separately beside a binary if you use restic-backed storage or backups.
Follow the [quick start](../../README.md#quick-start) or the
[deployment guide](../deployment.md). Source builds require Go 1.26.11 or
newer; building the console also requires Node.js 22 and pnpm.

Check archives against `checksums.txt` and verify signed build provenance.
Verify container image provenance and pin the verified digest. For example:

```sh
gh attestation verify gos3_0.3.2_linux_amd64.tar.gz \
  --repo seanmmitchell/gos3 --source-ref refs/heads/main
gh attestation verify oci://ghcr.io/seanmmitchell/gos3:0.3.2 \
  --repo seanmmitchell/gos3 --source-ref refs/heads/main
```

## Upgrading from 0.3.1

1. Back up backing data, metadata, settings, credentials, encryption keys and
   restic repositories. Keep the backup for rollback; see the
   [backup guide](../operations.md#backups).
2. Upgrade the binary or image and restart. Deploy the standalone web console
   from the same release if used. Source builds require Go 1.26.11 or newer.
3. Confirm `gos3 version` and `/_gos3/ready`, test a signed upload and read,
   and check console version labels. Existing configuration and storage
   formats do not require a migration for this patch.

Earlier-version upgrades also need their release notes, including the
[0.3.1 checklist](0.3.1.md#upgrading-from-030). Keep the previous binary or
image and the backup for rollback. Reverting restores the security issues
fixed here; a backup is the reliable recovery path if an older build cannot
read data written by a newer one.

## Known limits

Independent servers do not form a distributed cluster. STS/session tokens,
AWS KMS, SSE-C and erasure coding remain unavailable. Replicas and mirror jobs
do not replace backups. The retained `deepmerge` patch remains necessary until
an upstream fix is available. See the [compatibility reference](../s3-compatibility.md),
[security guide](../security.md) and [Dependabot alerts](https://github.com/seanmmitchell/gos3/security/dependabot)
for newly disclosed findings after this release.
